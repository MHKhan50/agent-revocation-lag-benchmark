# Dataset card: RevocationLag synthetic scenarios

## Summary
A deterministic CSV of 1,800 generated action traces for comparing authorization policies when a tool capability is revoked during a workflow.

## Intended uses
- Teaching runtime authorization and time-of-check/time-of-use concepts.
- Reproducing the included simulator.
- Testing metric code and policy implementations.
- Developing dissertation hypotheses before moving to more realistic, safely sandboxed traces.

## Not intended for
- Estimating real-world agent incident rates.
- Certifying the security of a model, framework, sandbox, or product.
- Training a production security classifier without additional validation.
- Representing any real user, organisation, incident, or system.

## Fields
- `scenario_id`: stable ID derived from seed and episode number.
- `seed`: generator seed (`17`, `29`, or `43`).
- `episode`: 1-based episode number within a seed.
- `plan_length`: number of action positions.
- `revoke_at`: zero-based position; revocation is effective before this action.
- `action_types`: compact trace string; `B` is benign, `S` requires the revoked capability.

Each scenario includes at least one sensitive action at or after `revoke_at`. The generator is in `generate_dataset.py`.

## Provenance, bias and limits
Generated by included Python code using fixed seeds. No external dataset, scraped content, personal data, or model output is included. The generator uses a simple 42% sensitive-action probability before ensuring at least one sensitive action after revocation. This is artificial, not fitted to deployed systems. It contains one capability, a fixed plan, one revocation event, and no concurrent calls or network faults.
